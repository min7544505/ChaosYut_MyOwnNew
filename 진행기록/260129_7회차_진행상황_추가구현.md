### 3. ResetToWaiting 함수 구현

**역할:** 말이 잡혔을 때 대기 위치로 돌아가게 하는 함수

**구현된 로직:**
```
[ResetToWaiting]
    ↓
[GET CurrentRoad] → [IsValid?]
    ├── True → [OnPieceExit(Self)]
    └── False → (스킵)
    ↓
[SET CurrentRoad = None]
    ↓
[SET CarrierPiece = None]
    ↓
[GET StackedPieces] → [For Each Loop]
    │
    └── Loop Body: [Element.ResetToWaiting()] ← 재귀 호출
    │
    └── Completed → [StackedPieces.Clear]
    ↓
[GET WaitingPosition] → [SetActorLocation]
```

**핵심 포인트:**
- **바닥 말만 잡으면** 재귀로 업힌 말들도 자동 리셋
- CurrentRoad가 None인 말(대기 중/업힌 말)은 OnPieceExit 스킵

### 4. MoveTo 함수에 잡기 로직 추가

**Source:** 6회차 계획 - 잡기/업기 로직 구현

**추가된 위치:** OnPieceEnter 이후, NextRoads.Length 체크의 False 핀에서

**구현된 로직:**
```
[For Each Loop: OccupyingPieces]
    ↓
[Array Element == Self?]
    ├── True → (스킵)
    └── False
        ↓
    [TeamIndex == TeamIndex?]
        │
        ├── True (같은 팀) → [Self.StackWith(Array Element)]
        │
        └── False (다른 팀 = 잡기!)
            ↓
        [Array Element.CarrierPiece] → [IsValid?]
            │
            ├── True (업힌 말) → [CarrierPiece.ResetToWaiting()]
            │
            └── False (바닥 말) → [Array Element.ResetToWaiting()]
```

**핵심 포인트:**
- **Self 체크 필수**: 자기 자신을 업거나 잡지 않도록
- **바닥 말 찾기**: CarrierPiece가 None이면 바닥 말, 있으면 CarrierPiece가 바닥 말

### 5. StackWith 함수 구현 (업기)

**역할:** 나(Self)를 OtherPiece(또는 그의 바닥 말)에게 업히게 하는 함수

| 항목 | 값 |
|------|-----|
| **Input** | OtherPiece (BP_YutPiece) |
| **Output** | None |

**구현된 로직:**
```
[StackWith(OtherPiece)]
    ↓
[GET OtherPiece.CarrierPiece] → [IsValid?]
    │
    ├── True → [SET BottomPiece = OtherPiece.CarrierPiece]
    └── False → [SET BottomPiece = OtherPiece]
    ↓
[GET Self.StackedPieces] → [For Each Loop]
    │
    └── Loop Body:
        [SET Element.CarrierPiece = BottomPiece]
        [BottomPiece.StackedPieces.Add(Element)]
    │
    └── Completed → [Self.StackedPieces.Clear]
    ↓
[BottomPiece.StackedPieces.Add(Self)]
    ↓
[SET Self.CarrierPiece = BottomPiece]
    ↓
[SET Self.CurrentRoad = None]
```

**핵심 포인트:**
- **Self = 새로 도착한 말 (업히는 쪽)**
- **OtherPiece = 이미 있던 말 (업는 쪽, 또는 그의 바닥 말)**
- **먼저 있던 말이 바닥 말이 됨**
- **내가 업고 있던 말들도 바닥 말에게 전달** (운전기사 변경)

## 학습한 개념

### 1. 바닥 말 vs 업힌 말 구조

| 역할 | CurrentRoad | CarrierPiece | StackedPieces |
|------|-------------|--------------|---------------|
| **바닥 말 (운전기사)** | ✅ 유지 | None | 업힌 말들 |
| **업힌 말 (승객)** | None | 바닥 말 참조 | 비어있음 |

### 2. 왜 업힌 말은 CurrentRoad = None인가?

- **동기화 문제 방지**: 바닥 말 이동 시 업힌 말들 전부 변경 불필요
- **OccupyingPieces 중복 방지**: Road에 바닥 말만 등록
- **위치 확인 방법**: `업힌말.CarrierPiece.CurrentRoad`

### 3. SET 노드의 핀 구조

```
┌─────────────────────────────┐
│ SET CarrierPiece            │
├─────────────────────────────┤
│ ○ Target ← "누구의" 변수    │
│ ○ CarrierPiece ← "어떤 값"  │
└─────────────────────────────┘

결과: Target.CarrierPiece = CarrierPiece값
```

### 4. 재귀 호출로 연쇄 리셋

```
A.ResetToWaiting() 호출
├── A.StackedPieces = [B, C]
│   ├── B.ResetToWaiting() ← 재귀
│   └── C.ResetToWaiting() ← 재귀
└── A 대기 위치로 이동
```

## 주요 설계 결정

### 1. 바닥 말만 Road에 등록
```
OccupyingPieces에는 CarrierPiece == None인 말만 등록
→ 잡기 판정 시 바닥 말만 검사하면 됨
```

### 2. 먼저 있던 말이 바닥 말
```
A가 먼저 있고 B가 도착 → A가 바닥 말
A 위에 B가 있고 C가 도착 → A가 바닥 말 (B, C 모두 업힘)
```

### 3. 업힌 말들도 바닥 말에게 전달
```
B[C를 업고 있음]가 A에게 업히면:
├── C.CarrierPiece = A (B → A로 변경)
├── A.StackedPieces = [C, B]
└── B.StackedPieces = [] (Clear됨)
```

## 대화 하이라이트

> **Q:** OtherPiece는 새로 들어온 돌인거 맞지?
> 
> **A:** ❌ 아닙니다! OtherPiece는 **이미 있던 말**이고, **Self가 새로 도착한 말**입니다. StackWith는 "나(Self)를 OtherPiece에게 업혀라"라는 의미입니다.

> **Q:** SET 노드에서 Target에 Array Element, CarrierPiece에 BottomPiece가 들어가면 BottomPiece.CarrierPiece가 C가 되는 거 아니야?
> 
> **A:** ❌ 아닙니다! Target은 "누구의" 변수를 수정할지, CarrierPiece 핀은 "어떤 값으로" 수정할지입니다. 결과는 `C.CarrierPiece = A` (C의 운전기사가 A로 설정됨)입니다.
